# NEXT STEP PLAN (2026-04-28)

## 目标

在“技术闭环已稳定”的前提下，进入业务定盘与试运营阶段，明确卖什么、卖给谁、怎么成交，并让官网、Workbench、内容产出统一到同一业务目标。

## 2026-05-02 拆分原则

接下来拆成两条 plan：

1. 商业内容 plan：负责套餐、履约、获客、内容、成交与试运营。
2. 系统 plan：负责官网、Workbench、API、通知、归因、验证和 harness 支撑。

优先级规则：

- 商业内容 plan 是主线，决定“做什么”和“怎么验证成交”。
- 系统 plan 是支撑线，决定“系统如何帮主线更快验证”。
- `harness` 只作为系统支撑，不再作为独立产品或新主线扩张。

## 分支计划

- [商业内容计划](BUSINESS_CONTENT_PLAN_2026-05-02.md)
- [系统支撑计划](SYSTEM_PLAN_2026-05-02.md)

## 当前优先顺序

1. 先做商业 P0-1：套餐与履约方案。
2. 再做商业 P0-2：获客类推广。
3. 然后做商业 P0-3：线索转化 SOP。
4. 系统侧只处理会直接阻塞以上三项的事项。
5. 最后进入 2 周小规模试运营复盘。

## 首期指标

- 线索量：每周新增有效线索数。
- 有效线索率：有效线索 / 总线索。
- 咨询预约率：预约咨询 / 有效线索。
- 成交率：成交 / 有效线索。
- 首次响应时长：线索创建到首次联系耗时。

## 风险与前提

- 若套餐、价格、履约资源未定，官网和内容会反复返工。
- 若获客内容没有归因，无法判断真实渠道质量。
- 若系统继续扩张 harness 或 Workbench 能力，会稀释业务验证速度。
- 试运营前需确保线上环境变量与本地一致，并保留 `verify:all` 作为发布前检查。
